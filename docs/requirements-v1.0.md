# 美容室シフト作成ツール 要件定義書 v1.0

作成日：2026-07-13　作成：AiRhyz　ステータス：ドラフト（前提条件の確定待ち箇所あり）

## 0. 前提条件（仮置き・要確認）

| 項目 | 仮置き内容 | 備考 |
| :---- | :---- | :---- |
| 利用先 | 単店舗でPoC後、SaaS化を見据える | マルチテナント設計を初期から意識 |
| 規模 | スタッフ5〜15名 | ソルバー計算量は本規模なら数秒以内 |
| シフト粒度 | v1：日単位の勤務パターン割当 | 時間単位割当はv2 |
| 技術スタック | Next.js＋Vercel／Python FastAPI＋OR-Tools（CP-SAT） | DB：PostgreSQL（Supabase想定） |

## 1. 目的・背景

美容室のシフト作成は、雇用形態の多様さ（正社員・パート・アルバイト・業務委託）、役職ランクとスキルの考慮、繁忙時間帯（平日夕方・土日祝日中）への適正配置、希望休の公平な反映といった制約が絡み合い、店長の大きな負担となっている。本ツールは制約ベースの自動作成により、シフト作成時間の大幅削減と、公平性・法令遵守・スタッフ満足度の向上を実現する。

## 2. ユーザーと権限

| 役割 | 権限 |
| :---- | :---- |
| オーナー／店長（管理者） | 全マスタ管理、相性マトリクス管理、自動作成実行、手動調整、確定・公開 |
| スタッフ | 希望休・希望シフト提出、確定シフト閲覧 |

相性マトリクスを含むセンシティブ情報は管理者権限のみ閲覧・編集可。スタッフ画面には一切表示しない。

## 3. 機能要件

### 3.1 マスタ管理

**スタッフマスタ**

- 基本情報：氏名、雇用形態（正社員／パート／アルバイト／業務委託）
- 役職ランク：スタイリスト／ジュニアスタイリスト／アシスタント
- スキルフラグ：カット、カラー、パーマ、シャンプー、受付、店締め（責任者可）等
- 労働条件：週・月の上限労働時間、月間公休日数、勤務可能曜日・時間帯
- 教育関係：教育担当者の指定（OJTペア用）

**店舗マスタ**

- 営業時間、定休日
- 曜日・時間帯別の必要人数（役職別に設定。例：土曜「スタイリスト3名以上＋アシスタント2名以上」）
- 勤務パターン定義：早番／遅番／通し／時短など（開始・終了時刻、休憩時間）

**相性マトリクス（管理者限定）**

| 区分 | 制約の扱い |
| :---- | :---- |
| NGペア | ソフト制約（強い減点）を既定とし、ペア単位でハード化を選択可 |
| 注意ペア | ソフト制約（中程度の減点） |
| 推奨ペア | ソフト制約（加点）。OJTペアと同一機構 |

- 緩和オプション：「同時出勤は許容するが、2名体制の時間帯では組ませない」設定
- 理由メモ欄（任意）を設け、事実ベースの運用を促す
- 3か月ごとの設定棚卸しリマインド

### 3.2 希望収集

- スタッフがスマホから希望休・希望勤務パターンを提出（月次サイクル）
- 提出期限の設定と未提出者への自動リマインド
- 管理者は提出状況を一覧で確認可能
- v1は自前フォーム、v2でLINE通知連携

### 3.3 自動作成エンジン（中核機能）

シフト作成を「勤務表の各マス目（スタッフ×日付）への勤務パターン割当問題」として定式化し、CP-SATソルバーで解く。

**ハード制約（絶対遵守）**

1. 曜日別の必要人数（役職・スキル別）の充足
2. 提出された希望休の反映
3. 連勤上限（既定6連勤、店舗設定で変更可）
4. 週・月の上限労働時間、月間公休日数の遵守
5. 店締め可能な責任者を毎営業日1名以上配置
6. ハード指定されたNGペアの同時出勤禁止
7. 労働基準法上の法定労働時間・休憩付与ルール

**ソフト制約（重み付きスコア最適化）**

1. 土日祝出勤・遅番回数の偏り平準化（公平性スコア）
2. 指名の多いスタイリストの繁忙帯（平日夕方・土日）優先配置
3. OJTペア・推奨ペアの同時出勤（加点）
4. NGペア・注意ペアの同時出勤回避（減点）
5. 希望勤務パターンとの一致度
6. 概算人件費の予算内収束

**解不能時のハンドリング**

- 制約充足解が存在しない場合、原因となった制約（人数不足の日、NGペア過多等）を特定して管理者に提示
- 緩和候補（ソフト化推奨制約）のサジェスト

### 3.4 調整・確定・共有

- 生成結果のカレンダーUI表示（スタッフ×日付マトリクス）
- ドラッグ＆ドロップによる手動調整。違反発生時は即時に警告表示（違反内容と対象制約を明示）
- 調整理由・相性起因の警告は管理者画面のみに表示
- 確定操作でスタッフへ一括公開・通知

### 3.5 出力・集計

- 月間シフト表のExcel／PDF出力（店内掲示用）
- 個人別の労働時間・出勤日数・土日出勤回数の自動集計
- 概算人件費の月次サマリ

## 4. 非機能要件

| 項目 | 要件 |
| :---- | :---- |
| 性能 | 15名×31日規模の自動作成を10秒以内に完了 |
| セキュリティ | 相性マトリクス等センシティブ情報はロールベースアクセス制御。通信TLS、保存時暗号化 |
| 可用性 | Vercel＋マネージドDBによる標準構成。PoC段階ではSLA要件なし |
| 拡張性 | マルチテナント（店舗ID分離）を初期スキーマから組み込む |
| 操作性 | スタッフ側はスマホ完結・説明不要のUI。管理者側もPC・タブレット対応 |

## 5. 段階リリース計画

| フェーズ | スコープ |
| :---- | :---- |
| v1（MVP） | マスタ管理／希望収集フォーム／自動作成（ハード＋ソフト制約）／手動調整／Excel出力 |

## 6. システム構成（v1）

- フロントエンド：Next.js（App Router）、Vercelにデプロイ
- 最適化API：Python FastAPI＋Google OR-Tools（CP-SAT）。コンテナ化しCloud Run等で稼働
- DB：PostgreSQL（Supabase）。認証はSupabase Auth
- 帳票出力：openpyxlによるExcel生成

## 8. 主要リスクと対策

1. NGペア設定過多による解不能：ソフト制約既定＋原因提示＋緩和サジェストで対応
2. 希望休集中日（土日・連休）の人員不足：不足日を事前警告し、調整依頼リストを自動生成
3. 制約重みのチューニング難：店長による生成結果の採点フィードバックを収集し、重みを段階調整
4. スタッフの希望提出率低迷：リマインド自動化と提出2タップ以内のUI設計
